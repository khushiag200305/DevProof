How it works

Every verdict comes from rules you can read, not a black-box model. DevProof never says someone does or doesn't know a skill, only whether public evidence supports the claim.

  1. Upload a resumeDevProof reads the name, skills, projects and GitHub link from the PDF.
  2. Scan GitHubThe 10 most recently updated repositories are scanned folder by folder: source files, dependencies, Dockerfiles, notebooks.
  3. Score each skillA 0–100 score per claimed skill from its best repository, with the evidence behind it.
  4. Close the gapsInterview questions, practice quizzes and recruiter skill tests cover what GitHub can't show.

For students

See your resume the way a recruiter checking your GitHub would, and know what to build next.

  • Skill report with the reason for every verdict and the repository that proves it.
  • Match a job: paste a job description or pick a role, see which resume fits best, and get a roadmap that names the repository each missing skill fits into.
  • Practice quizzes: 460 questions across 46 skills, with explanations.
  • Public portfolio link and suggested resume lines built from your real projects.

For recruiters

Search by what students have built, not by keywords on a page.

  • Talent search by skill and evidence strength, recent GitHub activity and original repositories.
  • Saved searches that tell you when a new student matches, a shortlist with private notes, and side-by-side comparison.
  • Skill tests: send a short timed quiz and see the score next to the GitHub evidence.
  • Recruiter accounts are approved by an admin before they can see any student.

The scoring rule

Each repository is scored for each claimed skill; the best repository counts. The last two points only apply to a repository that shows the skill, so an active but unrelated repository adds nothing.
